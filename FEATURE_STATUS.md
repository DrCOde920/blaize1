## 2. Classification Definitions

To prevent fixtures or mocks from being counted as live execution, every feature and action path is classified using the strict repository taxonomy:

- **`REAL`**: Performs the claimed operation end-to-end with genuine side effects (real cryptography, real network/API call, real DOM/file/AST operation) and verifiable independent evidence.
- **`PARTIAL`**: Contains real domain logic, validation, or cryptography for part of the flow, but relies on in-memory volatile storage, missing OS/backend wiring, or simulated downstream execution.
- **`SIMULATED`**: Mutates deterministic in-memory state or returns fixture data while presenting the result as an executed/verified/connected outcome.
- **`STUB`**: Hardcoded return value, no-op function, or static placeholder with no meaningful execution logic.
- **`UNSUPPORTED`**: Requires native OS/Electron/hardware capabilities unavailable in the current web/Node container runtime.
- **`NOT_CONFIGURED`**: Code path exists for live integration, but required external credentials, OAuth client secrets, or provider API keys are absent.
